# Техническое задание для Codex / Coding Agent

# Проект: «Розпочни своє навчання в NOVUS»

## 1. Назначение документа

Этот документ описывает требования к разработке статической веб-страницы-помощника для новых сотрудников магазинов NOVUS. Страница должна открываться после сканирования QR-кода и помогать пользователю самостоятельно выбрать способ входа в обучение: через Telegram-бот или через СДН «Супутник».

Документ предназначен для разработки с помощью Codex / coding agent и должен быть понятен как разработчику, так и техническому архитектору, product owner и тестировщику.

Отдельный файл `DESIGN.md` содержит подробные требования к визуальному стилю, экранам, UX-логике и адаптивности.

---

## 2. Контекст проекта

Компания NOVUS расширяется в регионы. Нужно быстро и удобно обрабатывать большое количество новых внешних сотрудников магазинов и давать им понятную инструкцию, чтобы они могли самостоятельно войти в обучение и пройти необходимые процессы без помощи администраторов.

Пользователи будут сканировать QR-код на телефоне и попадать на специальную страницу-помощник. Основная задача страницы — не обучать полноценно, а провести пользователя по простому маршруту:

1. выбрать удобный способ входа;
2. посмотреть короткую видеоинструкцию;
3. при необходимости установить Telegram;
4. при входе через СДН получить подсказку по добавлению ярлыка на главный экран смартфона;
5. перейти в Telegram-бот или СДН.

---

## 3. Цели проекта

### 3.1. Основная цель

Создать простую, понятную и устойчивую мобильную веб-страницу, которая помогает новым сотрудникам NOVUS самостоятельно начать обучение.

### 3.2. Бизнес-цели

- Снизить нагрузку на администраторов и сотрудников поддержки.
- Упростить первый вход в обучение для новых сотрудников магазинов.
- Минимизировать количество ошибок и вопросов при старте обучения.
- Сформировать единый понятный маршрут входа через QR-код.
- Приоритизировать использование Telegram-бота как основного способа входа.
- Оставить СДН «Супутник» как альтернативный способ.

### 3.3. Пользовательские цели

Пользователь должен:

- открыть страницу по QR-коду;
- понять, что делать дальше;
- выбрать Telegram-бот или СДН;
- получить короткую инструкцию;
- перейти в выбранный канал;
- при входе через СДН понять, как добавить ярлык на главный экран смартфона;
- иметь возможность обратиться за помощью по телефону.

## 4. Целевая аудитория

### 4.1. Основная аудитория

Новые внешние сотрудники магазинов NOVUS.

### 4.2. Особенности аудитории

- Пользователи используют личные телефоны.
- Ожидается больше Android-устройств, но iOS должен поддерживаться одинаково хорошо.
- Часть пользователей может иметь низкий уровень цифровой грамотности.
- Интерфейс должен быть простым, крупным, понятным и без технических терминов.
- Язык интерфейса — украинский.
- Обращение к пользователю — на «ти».

---

## 5. Общая концепция продукта

Страница работает как мини-мастер запуска обучения.

Пользователь попадает на страницу по QR-коду и видит приветственный экран с двумя вариантами:

1. `Увійти через Telegram-бот` — приоритетный путь.
2. `Увійти через СДН «Супутник»` — альтернативный путь.

Если пользователь выбирает СДН, перед переходом в СДН один раз показывается модальное окно, которое мягко объясняет, почему Telegram-бот удобнее, и предлагает попробовать Telegram. Пользователь может отказаться и продолжить путь через СДН.

## 6. MVP

### 6.1. Состав MVP

MVP должен быть реализован как статический сайт без сборщиков и backend-части.

Минимальная структура файлов:

```text
index.html
styles.css
app.js
config.js
manifest.json
sw.js
assets/
  logo/
  hero/
  instructions/
  icons/
```

### 6.2. Что должно быть в MVP

- Mobile-first интерфейс.
- Адаптация под ПК.
- Приветственный экран с героем/персонажем и двумя кнопками.
- Ветка Telegram:
  - проверка наличия Telegram у пользователя через вопрос;
  - переход к видеоинструкции, если Telegram есть;
  - предложение установить Telegram, если его нет;
  - автоматический выбор App Store / Google Play по устройству;
  - возможность отказаться от установки и перейти в ветку СДН;
  - переход в Telegram-бот.
- Ветка СДН:
  - модальное окно с аргументом в пользу Telegram при первом выборе СДН;
  - видеоинструкция;
  - инструкция по добавлению ярлыка на главный экран смартфона;
  - отдельная логика для iOS и Android;
  - слайдер с шагами инструкции;
  - основная кнопка `Я додав(-ла) ярлик, перейти в СДН`;
  - маленькая ссылка `Не виходить? Пропустити`;
  - переход в СДН в этой же вкладке.
- Кнопка помощи на всех экранах.
- Весь контент и ссылки должны редактироваться через `config.js`.
- Видео должны поддерживать несколько типов источников:
  - прямой MP4-файл;
  - YouTube embed;
  - внешний URL как fallback.
- Страница не должна собирать персональные данные.
- Аналитика не нужна.

### 6.3. Что не входит в MVP

- Админка.
- Backend.
- Авторизация на странице-помощнике.
- Персональные QR-коды.
- Персонализация по пользователю.
- Сбор статистики.
- Проверка фактического добавления ярлыка на главный экран.
- Интеграция с API СДН.
- Интеграция с API Telegram.

## 7. Production-вариант

Production-вариант должен быть совместим с MVP, но предусматривать возможность дальнейшего развития.

### 7.1. Возможные улучшения production-версии

- Размещение на корпоративном домене NOVUS или внутри СДН.
- Замена GitHub Pages без изменения логики приложения.
- PWA manifest и service worker для более удобного добавления ярлыка на Android.
- Более качественные изображения для инструкций iOS/Android.
- Возможность заменить видео без изменения кода.
- Возможность добавить новые сценарии через `config.js`.
- Возможность добавить несколько языков в будущем, если потребуется.
- Возможность подключить аналитику в будущем, но в текущем проекте она отключена.

### 7.2. Production-ограничения

- Даже в production нельзя гарантированно создать ярлык на iOS программно.
- Нельзя технически проверить, добавил ли пользователь ярлык.
- Нельзя гарантировать, что QR откроется именно в Safari на iOS.
- Нельзя гарантировать, что ссылка `t.me/...` откроется в приложении Telegram, если оно не установлено.

## 8. Функциональные требования

## 8.1. Общие требования

### FR-001. Открытие по QR-коду

Страница должна корректно открываться по публичной ссылке, которую можно зашить в QR-код.

### FR-002. Один общий сценарий

Для всех пользователей используется один общий сценарий. Персональные ссылки и персональные параметры не требуются.

### FR-003. Украинский язык

Весь пользовательский интерфейс должен быть на украинском языке.

### FR-004. Обращение на «ти»

Все тексты должны обращаться к пользователю на «ти».

### FR-005. Mobile-first

Интерфейс должен быть оптимизирован в первую очередь под смартфоны.

### FR-006. Поддержка ПК

На ПК интерфейс должен отображаться корректно, без растягивания на всю ширину экрана. Контент должен быть ограничен центральной колонкой.

### FR-007. Кнопка помощи

На всех экранах должна быть доступна кнопка помощи. При нажатии должна открываться ссылка `tel:` с номером администратора из `config.js`.

---

## 8.2. Конфигурационный файл

### FR-008. Вынесение контента в config.js

Все изменяемые данные должны находиться в `config.js`:

- название страницы;
- логотип;
- изображение героя;
- ссылки;
- тексты экранов;
- подписи кнопок;
- ссылки на видео;
- пути к изображениям инструкций;
- телефон помощи;
- настройки PWA;
- ссылки на App Store / Google Play;
- URL Telegram-бота;
- URL СДН.

### FR-009. Глобальный объект конфигурации

`config.js` должен создавать глобальный объект:

```js
window.NOVUS_CONFIG = { ... };
```

### FR-010. Устойчивость к неполной конфигурации

Если в `config.js` не заполнены отдельные поля, приложение не должно падать. Нужно показывать безопасные заглушки.

## 8.3. Приветственный экран

### FR-011. Заголовок

На первом экране должен отображаться заголовок:

```text
Розпочни своє навчання в NOVUS
```

### FR-012. Приветствие

На первом экране должен отображаться текст:

```text
Вітаю!
Зараз я допоможу тобі налаштувати все необхідне для початку навчання.
Обери зручний спосіб входу:
```

### FR-013. Герой/персонаж

На первом экране должно быть изображение героя/персонажа. Путь к изображению задаётся в `config.js`.

### FR-014. Две основные кнопки

На первом экране должны быть две кнопки:

```text
Увійти через Telegram-бот
Увійти через СДН «Супутник»
```

## 8.4. Telegram-сценарий

### FR-015. Проверка наличия Telegram

После выбора Telegram-бота пользователь должен увидеть вопрос:

```text
Для входу через Telegram-бот потрібен застосунок Telegram.
У тебе вже встановлений Telegram?
```

Кнопки:

```text
Так, Telegram є
Ні, Telegram немає
Обрати інший спосіб
```

### FR-016. Если Telegram установлен

Если пользователь нажимает `Так, Telegram є`, приложение открывает экран с видеоинструкцией Telegram.

### FR-017. Если Telegram не установлен

Если пользователь нажимает `Ні, Telegram немає`, приложение показывает экран установки Telegram.

### FR-018. Установка Telegram

Экран установки должен объяснять, что Telegram нужен для работы с Telegram-ботом, и содержать кнопки:

```text
Встановити Telegram
Я встановив(-ла) Telegram
Не хочу встановлювати, перейти через СДН
Назад
```

### FR-019. Автоматический выбор магазина приложений

Кнопка `Встановити Telegram` должна вести:

- на App Store для iOS;
- на Google Play для Android;
- на официальный сайт Telegram или fallback URL для других устройств.

Ссылки должны задаваться в `config.js`.

### FR-020. Текст после установки Telegram

На экране установки должен быть текст:

```text
Після встановлення повернись до цієї сторінки або знову відскануй QR-код.
```

### FR-021. Отказ от установки Telegram

Если пользователь не хочет устанавливать Telegram, приложение автоматически переводит его в ветку СДН.

### FR-022. Видеоинструкция Telegram

Видеоинструкция Telegram должна отображаться на странице. Пользователь должен иметь кнопку:

```text
Я переглянув(-ла), перейти в Telegram-бот
```

Также нужна кнопка:

```text
Обрати інший спосіб
```

### FR-023. Переход в Telegram-бот

После подтверждения пользователь переходит по ссылке Telegram-бота из `config.js`. Переход выполняется в этой же вкладке.

## 8.5. СДН-сценарий

### FR-024. Модальное окно при выборе СДН

Если пользователь на первом экране выбирает СДН, нужно один раз показать модальное окно с аргументом в пользу Telegram-бота.

Пример текста:

```text
Telegram-бот зазвичай зручніший: він допоможе швидше отримати доступ до навчання та підкаже наступні кроки.
```

Кнопки:

```text
Спробувати Telegram
Все одно перейти в СДН
```

### FR-025. Показывать модальное окно только один раз

Модальное окно должно показываться только один раз за текущую сессию пользователя. Если пользователь уже отказался, повторно не показывать.

### FR-026. Видеоинструкция СДН

После выбора СДН пользователь должен увидеть видеоинструкцию СДН.

Текст:

```text
Вхід через СДН «Супутник»
Подивись коротку інструкцію. У ній показано, як зайти в навчання та відкрити потрібний курс.
```

Кнопки:

```text
Я переглянув(-ла), продовжити
Обрати інший спосіб
```

### FR-027. Объяснение логина и пароля

На СДН-ветке нужно объяснить:

```text
Твій логін — це табельний номер на зворотній стороні бейджа.
Перший пароль також вказаний на зворотній стороні бейджа.
```

Важно: не показывать общий пароль на странице.

### FR-028. Инструкция по добавлению ярлыка

После видеоинструкции СДН нужно показать инструкцию по добавлению ярлыка на главный экран смартфона.

### FR-029. Мягко обязательный ярлык

Основная кнопка после инструкции:

```text
Я додав(-ла) ярлик, перейти в СДН
```

Маленькая ссылка ниже:

```text
Не виходить? Пропустити
```

Обе ведут в СДН.

### FR-030. Переход в СДН

Переход в СДН выполняется в этой же вкладке по URL:

```text
https://sdn.novus.ua/default?mode=default
```

URL должен задаваться в `config.js`.

## 8.6. Инструкции по ярлыку

### FR-031. Определение устройства

Приложение должно определять тип устройства:

- iOS;
- Android;
- desktop/other.

### FR-032. Определение браузера на iOS

Для iOS приложение должно попытаться определить, открыт ли сайт в Safari.

Если сайт открыт не в Safari или во встроенном браузере, инструкция должна сначала показать шаг:

```text
Відкрий цю сторінку в Safari.
```

Если сайт открыт в Safari, этот шаг не показывать.

### FR-033. Инструкция iOS

Инструкция iOS должна быть слайдером с шагами и изображениями-заглушками.

Пример шагов:

1. Відкрий сторінку в Safari.
2. Натисни кнопку «Поділитися».
3. Обери «На екран Домівка».
4. Натисни «Додати».
5. Тепер значок СДН з’явиться на головному екрані.

Первый шаг показывать только если браузер не Safari.

### FR-034. Инструкция Android

Инструкция Android должна быть слайдером с шагами и изображениями-заглушками.

Пример шагов:

1. Натисни меню ⋮ у правому верхньому куті.
2. Обери «Додати на головний екран».
3. Натисни «Додати».
4. Тепер значок СДН з’явиться на головному екрані.

### FR-035. Инструкция desktop/other

Если сайт открыт на ПК или неизвестном устройстве, нужно показать текст:

```text
Цей крок потрібен для смартфона. Якщо ти зараз на комп’ютері, можеш перейти в СДН напряму.
```

## 8.7. Слайдер инструкций

### FR-036. Слайдер шагов

Слайдер должен отображать один шаг за раз.

### FR-037. Навигация слайдера

Слайдер должен иметь понятные кнопки:

```text
Назад
Далі
```

### FR-038. Прогресс слайдера

Внизу слайдера должен быть визуальный прогресс-бар или индикатор шагов. Прогресс должен заполняться по мере перехода между шагами.

### FR-039. Подпись шага

Каждый шаг должен иметь подпись:

```text
Крок 1 з 4
```

### FR-040. Последний шаг

На последнем шаге кнопка `Далі` должна заменяться на:

```text
Готово
```

После нажатия `Готово` показывается финальный блок с кнопками перехода в СДН.

## 8.8. Видео

### FR-041. Универсальный видео-компонент

Нужно реализовать компонент, который умеет отображать видео из разных источников:

- `type: "youtube"`;
- `type: "mp4"`;
- `type: "iframe"`;
- `type: "placeholder"`.

### FR-042. Видео не блокирует сценарий

Пользователь может нажать `Я переглянув(-ла)` без технической проверки досмотра видео.

### FR-043. Плейсхолдер видео

Если ссылка на видео не задана, показывать аккуратный плейсхолдер:

```text
Тут буде відеоінструкція
```

## 9. Нефункциональные требования

### NFR-001. Простота

Приложение должно работать без backend, без сборки и без сложной инфраструктуры.

### NFR-002. Производительность

Страница должна быстро открываться на мобильном интернете. Изображения должны быть оптимизированы.

### NFR-003. Доступность

Интерфейс должен иметь:

- крупные кнопки;
- контрастный текст;
- читаемые шрифты;
- понятные состояния фокуса;
- alt-тексты для изображений;
- управление с клавиатуры для desktop.

### NFR-004. Надёжность

Если внешние изображения или видео не загрузились, приложение должно продолжать работать.

### NFR-005. Совместимость

Поддерживаемые браузеры:

- Chrome Android;
- Samsung Internet;
- Safari iOS;
- Chrome iOS;
- Edge/Chrome desktop;
- Safari desktop.

### NFR-006. Безопасность

Страница не должна собирать, сохранять или отправлять персональные данные.

### NFR-007. Конфиденциальность

На странице нельзя показывать общий пароль первого входа.

MVP реализуется как статический сайт:

app.js

manifest.json

### 10.1.1. index.html

## 12. Состояния приложения

Приложение должно работать как state machine.

### 12.1. Список экранов

```text
welcome
telegram-check
telegram-install
telegram-video
sdn-preference-modal
sdn-video
sdn-login-hint
shortcut-instruction
shortcut-complete
```

### 12.2. Основные переходы

```text
welcome
├── choose telegram → telegram-check
└── choose sdn → sdn-preference-modal → sdn-video

telegram-check
├── telegram exists → telegram-video
├── telegram not installed → telegram-install
└── choose another way → welcome

telegram-install
├── install telegram → external app store
├── installed telegram → telegram-video
├── do not install → sdn-video
└── back → telegram-check

telegram-video
├── watched → telegram bot external link
└── choose another way → welcome

sdn-video
├── watched → sdn-login-hint / shortcut-instruction
└── choose another way → welcome

shortcut-instruction
├── completed → sdn external link
└── skip → sdn external link
```

## 13. Device/browser detection

### 13.1. Требования

Нужно реализовать функции:

```js
getDeviceType(); // "ios" | "android" | "desktop" | "unknown"
isSafariOnIOS(); // true | false
isInAppBrowser(); // true | false | "unknown"
```

### 13.2. Назначение

Эти функции нужны не для безопасности, а для выбора правильной инструкции.

### 13.3. Важно

User-agent detection не должен быть единственным критичным механизмом. Если браузер не определён, показывать универсальную безопасную инструкцию.

|---|---|---|
| Нельзя автоматически создать ярлык на iOS | iOS требует ручного действия пользователя | Показывать пошаговую инструкцию и не блокировать полностью переход |
