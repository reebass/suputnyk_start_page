# DESIGN.md

# Дизайн и UX-спецификация

# Проект: «Розпочни своє навчання в NOVUS»

## 1. Назначение документа

Этот документ описывает визуальный стиль, UX-логику, экраны, компоненты и адаптивное поведение веб-страницы-помощника для входа новых сотрудников NOVUS в обучение.

Документ дополняет основное техническое задание и должен использоваться разработчиком/Codex при создании интерфейса.

---

## 2. Ключевая UX-идея

Страница должна ощущаться не как техническая инструкция, а как простой дружелюбный помощник.

Пользователь должен понимать:

- где он находится;
- что нужно сделать сейчас;
- какая кнопка главная;
- как вернуться назад;
- как попросить помощь.

На одном экране не должно быть много текста, много вариантов или технических терминов.

---

## 3. Аудитория и UX-принципы

### 3.1. Аудитория

Новые внешние сотрудники магазинов NOVUS, которые используют личные смартфоны.

### 3.2. Особенности

- Часть пользователей может быть неуверенной в технологиях.
- Возможны пользователи старшего возраста.
- Пользователь может сканировать QR-код в шумной среде магазина.
- Пользователь может торопиться.
- Пользователь может не понимать разницу между браузером, приложением, СДН и Telegram.

### 3.3. UX-принципы

1. Один экран — одно основное действие.
2. Главная кнопка всегда визуально сильнее остальных.
3. Тексты короткие и человеческие.
4. На каждом экране есть помощь.
5. Есть возможность вернуться назад.
6. Нельзя использовать технический жаргон.
7. Нельзя перегружать пользователя выбором.
8. Интерфейс должен быть удобен пальцем.
9. Ошибки пользователя должны быть безопасными.
10. СДН-путь должен быть доступен, но Telegram — приоритетный.

## 4. Бренд и визуальный стиль

### 4.1. Цвета

Основные цвета NOVUS:

```text
Primary green: #42AC35
Dark green:    #117407
White:         #FFFFFF
```

Рекомендуемые дополнительные цвета:

```text
Text primary:     #1F2933
Text secondary:   #52606D
Background soft:  #F7FBF6
Border soft:      #D9EBD6
Error/attention:  #B42318
Warning soft:     #FFF7E6
Disabled:         #A0A7B0
```

### 4.2. Использование цветов

- Основная кнопка: `#42AC35`.
- Hover/focus основной кнопки: `#117407`.
- Фон страницы: `#FFFFFF` или очень светлый зелёный `#F7FBF6`.
- Текст: тёмный нейтральный.
- Второстепенные кнопки: белый фон, зелёная рамка.
- Предупреждения и подсказки: мягкие светлые карточки.

### 4.3. Общий визуальный тон

- Минимализм.
- Много воздуха.
- Крупные кнопки.
- Мягкие скругления.
- Без визуального шума.
- Без длинных текстовых блоков.
- Интерфейс должен выглядеть современно, но не «сложно».

## 5. Типографика

### 5.1. Шрифт

Использовать системный стек:

```css
font-family: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

### 5.2. Размеры на мобильных

```text
Page title:       28–32 px
Screen title:     24–28 px
Body text:        18–20 px
Small text:       15–16 px
Button text:      18–20 px
Help text:        15–16 px
```

### 5.3. Размеры на desktop

```text
Page title:       36–44 px
Screen title:     28–32 px
Body text:        18–20 px
Button text:      18–20 px
```

### 5.4. Межстрочный интервал

```text
Headings: 1.15–1.25
Body:     1.45–1.6
Buttons:  1.2
```

## 6. Layout

### 6.1. Mobile-first

На мобильном экране интерфейс должен занимать всю ширину с внутренними отступами.

```text
Mobile padding: 16–20 px
Card padding:   20–24 px
Button height:  56–64 px
```

### 6.2. Desktop

На desktop контент должен быть по центру.

```text
Max content width: 560–680 px
Desktop padding:   32–48 px
```

Не растягивать карточку на всю ширину экрана.

### 6.3. Основная композиция

```text
[Logo / optional]
[Hero image]
[Title]
[Short text]
[Primary action]
[Secondary action]
[Help button]
```

## 7. Компоненты

## 7.1. App shell

Общий контейнер страницы.

Содержит:

- логотип;
- основной контент текущего экрана;
- кнопку помощи;
- optional footer.

## 7.2. Card

Основной контент лучше размещать в карточке.

```text
Background: #FFFFFF
Border: 1px solid #D9EBD6
Border radius: 24 px
Box shadow: мягкая, ненавязчивая
Padding: 20–28 px
```

## 7.3. Button primary

Используется для главного действия.

```text
Background: #42AC35
Text: #FFFFFF
Height: 56–64 px
Border radius: 16–18 px
Font weight: 700
```

Примеры:

```text
Увійти через Telegram-бот
Я переглянув(-ла), продовжити
Я додав(-ла) ярлик, перейти в СДН
```

## 7.4. Button secondary

Используется для альтернативного действия.

```text
Background: #FFFFFF
Text: #117407
Border: 2px solid #42AC35
Height: 54–60 px
Border radius: 16–18 px
Font weight: 650
```

## 7.5. Text link / subtle action

Используется для менее желательного действия.

Пример:

```text
Не виходить? Пропустити
```

Стиль:

```text
Small text
Underline optional
Color: #52606D или #117407
```

Важно: ссылка должна быть видимой, но слабее основной кнопки.

## 7.6. Help button

Кнопка помощи должна быть доступна на всех экранах.

Рекомендуемый вариант:

```text
Потрібна допомога? Зателефонувати адміністратору
```

На мобильном можно сделать компактнее:

```text
☎ Допомога
```

Поведение:

```text
tel:HELP_PHONE
```

## 7.7. Video block

Карточка видео.

Если видео не задано:

```text
Тут буде відеоінструкція
```

Плейсхолдер должен выглядеть аккуратно, не как ошибка.

## 7.8. Modal

Модальное окно для предложения Telegram при выборе СДН.

Требования:

- затемнение фона;
- карточка по центру;
- короткий текст;
- две кнопки;
- не выглядеть как ошибка;
- не быть агрессивным.

## 8. Экраны

## 8.1. Welcome screen

### Назначение

Первый экран после QR-кода. Пользователь должен понять, что он начинает обучение NOVUS и выбрать способ входа.

### Контент

Заголовок:

```text
Розпочни своє навчання в NOVUS
```

Приветствие:

```text
Вітаю!
Зараз я допоможу тобі налаштувати все необхідне для початку навчання.
Обери зручний спосіб входу:
```

Кнопки:

```text
Увійти через Telegram-бот
Увійти через СДН «Супутник»
```

### Визуал

- Логотип NOVUS сверху.
- Герой/персонаж на старте.
- Telegram-кнопка визуально может быть основной, так как это приоритетный путь.
- СДН-кнопка вторичная.

### UX-замечание

Не объяснять на первом экране все детали. Детали появляются после выбора.

---

## 8.2. Telegram check screen

### Назначение

Понять, установлен ли Telegram.

### Контент

```text
Для входу через Telegram-бот потрібен застосунок Telegram.
У тебе вже встановлений Telegram?
```

Кнопки:

```text
Так, Telegram є
Ні, Telegram немає
Обрати інший спосіб
```

### UX

- `Так, Telegram є` — primary.
- `Ні, Telegram немає` — secondary.
- `Обрати інший спосіб` — subtle.

---

## 8.3. Telegram install screen

### Назначение

Склонить пользователя установить Telegram, но дать возможность уйти в СДН.

### Контент

```text
Telegram допоможе швидше почати навчання та отримувати підказки в одному місці.

Щоб користуватися Telegram-ботом, потрібно встановити Telegram на телефон.
```

Дополнительный текст:

```text
Після встановлення повернись до цієї сторінки або знову відскануй QR-код.
```

Кнопки:

```text
Встановити Telegram
Я встановив(-ла) Telegram
Не хочу встановлювати, перейти через СДН
Назад
```

### UX

- Основная кнопка: `Встановити Telegram`.
- `Не хочу встановлювати...` должна быть доступной, но визуально слабее.

---

## 8.4. Telegram video screen

### Назначение

Показать короткую инструкцию перед переходом в Telegram-бот.

### Контент

```text
Подивись коротку інструкцію
У відео показано, як відкрити Telegram-бот і почати навчання.
```

Кнопки:

```text
Я переглянув(-ла), перейти в Telegram-бот
Обрати інший спосіб
```

### UX

Не блокировать кнопку до окончания видео.

---

## 8.5. SDN preference modal

### Назначение

Если пользователь сразу выбирает СДН, мягко предложить Telegram как более удобный путь.

### Контент

```text
Telegram-бот зазвичай зручніший: він допоможе швидше отримати доступ до навчання та підкаже наступні кроки.
```

Кнопки:

```text
Спробувати Telegram
Все одно перейти в СДН
```

### UX

- Показывать только один раз за сессию.
- Не использовать давление или сложные объяснения.
- Если пользователь отказался, уважать выбор.

---

## 8.6. SDN video screen

### Назначение

Показать инструкцию по входу в СДН.

### Контент

```text
Вхід через СДН «Супутник»
Подивись коротку інструкцію. У ній показано, як зайти в навчання та відкрити потрібний курс.
```

Подсказка:

```text
Твій логін — це табельний номер на зворотній стороні бейджа.
Перший пароль також вказаний на зворотній стороні бейджа.
```

Кнопки:

```text
Я переглянув(-ла), продовжити
Обрати інший спосіб
```

### UX

Подсказку про бейдж лучше оформить отдельной светлой карточкой.

---

## 8.7. Shortcut intro screen

### Назначение

Объяснить, зачем нужен ярлык.

### Контент

```text
Додай СДН на головний екран телефону

Так наступного разу ти зможеш відкрити навчання одним натисканням — як звичайний додаток.
```

Кнопка:

```text
Показати, як додати ярлик
```

### UX

Это важный шаг, но не должен выглядеть страшно или технически.

---

## 8.8. Shortcut slider screen

### Назначение

Пошагово показать, как добавить ярлык на смартфон.

### Структура одного слайда

```text
Крок 1 з 4
[Изображение]
Заголовок шага
Короткое объяснение
[Назад] [Далі]
[Прогресс-бар]
```

### Прогресс

Прогресс должен быть очень понятным:

- либо горизонтальная зелёная полоса;
- либо точки с активным шагом;
- предпочтительно полоса + подпись `Крок X з Y`.

### iOS не Safari

Если iOS открыт не в Safari, первым шагом добавить:

```text
Відкрий сторінку в Safari
Щоб додати значок на iPhone, сторінку потрібно відкрити саме в Safari.
```

### iOS Safari

Если iOS открыт в Safari, этот шаг не показывать.

### Android

Показывать Android-шаги.

### Desktop

Показывать fallback-экран, а не мобильный слайдер.

---

## 8.9. Shortcut complete / SDN final action

### Назначение

Финально подтолкнуть пользователя подтвердить добавление ярлыка и перейти в СДН.

### Контент

```text
Готово!
Тепер ти можеш відкривати СДН через значок на головному екрані.
```

Основная кнопка:

```text
Я додав(-ла) ярлик, перейти в СДН
```

Маленькая ссылка:

```text
Не виходить? Пропустити
```

### UX

Основная кнопка должна быть заметной. Ссылка `Пропустити` должна быть видимой, но слабее.

## 10. Responsive behavior

### 10.1. Mobile 320–480 px

- Одна колонка.
- Кнопки на всю ширину.
- Герой не должен занимать слишком много места.
- Отступы 16–20 px.
- Видео 16:9.
- Карточки без чрезмерных теней.

### 10.2. Tablet 768 px

- Одна центральная колонка.
- Max-width около 600 px.
- Можно увеличить отступы.

### 10.3. Desktop 1024+ px

- Центральная колонка.
- Max-width 640–680 px.
- Фон может быть светло-зелёным, карточка белая.
- Не растягивать кнопки слишком широко за пределами карточки.


Не подключать тяжёлые icon-библиотеки.

## 13. Текстовый стиль

### 13.1. Общие правила

- Украинский язык.
- Обращение на «ти».
- Простые короткие предложения.
- Не использовать слова: PWA, manifest, браузерный prompt, токен, авторизация API.
- Вместо «авторизуйся» лучше «увійди».
- Вместо «інсталюй» лучше «встанови».
- Вместо «десктоп» лучше «комп’ютер».

### 13.2. Примеры хорошего тона

```text
Натисни зелену кнопку нижче.
```

```text
Після встановлення повернись до цієї сторінки або знову відскануй QR-код.
```

```text
Твій логін — це табельний номер на зворотній стороні бейджа.
```

### 13.3. Избегать

```text
Виконайте інсталяцію PWA.
```

```text
Перейдіть за external URL.
```

```text
Ваші облікові дані знаходяться у системі.
```

## 14. Доступность

### 14.1. Touch targets

Минимальная высота кнопки:

```text
56 px
```

Минимальный отступ между кнопками:

```text
12 px
```

### 14.2. Контраст

Текст должен быть хорошо читаемым на белом фоне.

Не использовать светло-зелёный текст на белом фоне.

### 14.3. Focus states

Для клавиатуры на desktop должны быть заметные focus states.

### 14.4. Alt text

Все изображения должны иметь alt-тексты из config или безопасные fallback.

### 14.5. Motion

Анимации допустимы, но очень мягкие:

- fade;
- small slide;
- no flashy effects.

Уважать `prefers-reduced-motion`.

---

## 15. UI states

### 15.1. Normal

Обычное состояние кнопки.

### 15.2. Hover

На desktop кнопка слегка темнеет.

### 15.3. Active

Кнопка визуально нажимается.

### 15.4. Disabled

Если номер помощи или ссылка не заданы, кнопка должна быть disabled или показывать понятный fallback.

### 15.5. Loading

Если нужно показать загрузку видео или изображения, использовать мягкий placeholder.

### 15.6. Error/fallback

Текст ошибки должен быть человеческим:

```text
Не вдалося завантажити відео. Ти можеш продовжити далі.
```

---

## 16. Desktop fallback

Если пользователь открыл страницу на компьютере, интерфейс должен быть нормальным.

Для ярлыка показывать текст:

```text
Цей крок потрібен для смартфона. Якщо ти зараз на комп’ютері, можеш перейти в СДН напряму.
```

Кнопки:

```text
Перейти в СДН
Обрати інший спосіб
```

---

## 17. Что нельзя делать в дизайне

- Не делать длинную инструкцию одним большим текстом.
- Не использовать мелкий шрифт.
- Не прятать главную кнопку ниже экрана без причины.
- Не использовать больше трёх кнопок одинаковой важности на одном экране.
- Не делать Telegram-давление агрессивным.
- Не блокировать пользователя полностью, если он не смог добавить ярлык.
- Не использовать технические термины.
- Не показывать общий пароль на странице.
- Не делать интерфейс только под телефон без нормального вида на ПК.

---

## 18. Финальный визуальный ориентир

Страница должна выглядеть как:

```text
чистая мобильная карточка NOVUS
+ дружелюбный помощник
+ два понятных пути
+ короткие видео
+ пошаговые инструкции
+ большая зелёная кнопка для следующего действия
```

Главное ощущение для пользователя:

```text
«Я не загубився. Тут зрозуміло, що натискати далі.»
```
